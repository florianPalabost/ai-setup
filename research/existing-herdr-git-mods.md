# Existing git/GitHub mods for herdr

Research for issue #3 (map #2, "Herdr git & GitHub integration"). Captured 2026-11-02 against herdr-app **0.1.11**, which is the latest tag on `herdrdev/herdr-app` (`gh api repos/herdrdev/herdr-app/tags`: v0.1.11, v0.1.10, v0.1.9, …).

Question: what do herdr.dev/mods and GitHub repos tagged `herdr-mod` / `herdr-layout` offer for (1) a git graph, (2) the PR + CI checks of the current branch, (3) lists of my PRs and review requests? And what do the shipped mods already show for git?

Nothing was installed or copied into `~/.config/herdr-app`. The community sources were downloaded through `gh api` into a scratch folder and read as text. None of them was run.

## Sources and method

- **herdr.dev/mods** is rendered on the client. Its data is `https://assets.herdr.dev/mods/index.json`, generated `2026-11-02T11:30Z` from the query `topic:herdr-mod is:public`: 175 repos, 183 mods, 22 skipped. Layouts come from `https://assets.herdr.dev/layouts/index.json`: 86 repos, 110 layouts. The static HTML lists only the official example, `herdrdev/tmux-prefix`.
- **GitHub:** `gh api search/repositories?q=topic:herdr-mod` returns 175 repos and `topic:herdr-layout` returns 87, the same sets as the index. `gh search repos --topic herdr` also returns TUI plugins for the older herdr TUI. Those are a different runtime (not gpui-kit `mods/<name>/main.js`), so I left them out: `herdr-lazygit`, `herdr-gitview`, `herdr-reviewr` and others.
- **Herdr's rules** come from `~/.config/herdr-app/AGENTS.md`, under "Layouts and mods other people made" (l.410-463) and "Mods" (l.716+). Mods are trusted code: `exec` and `fetch` have no restrictions (l.928). Before adding a mod, the agent must say whether it reaches the network, runs programs (`exec`, `hc`) or reads files outside its folder (l.421-423). If the files don't work on this version, the mod is rebuilt from its `RECIPE.md` (l.428-431).
- **Per candidate:** I fetched the repo tree plus every `*.js`, `mod.json`, `RECIPE.md`, `README.md` and `keys.json`, then statically scanned the `exec(...)`, `hc(...)`, `fetch(...)` calls, the `herdr` imports and the timers.

"Recency" is the GitHub `pushed_at` date. The whole herdr-app mod ecosystem is less than 2 months old: the oldest herdr-app mod repo in this list was created 2026-09-24. So every candidate is "recent", and none has a track record yet.

## 1. What the shipped mods already show (`~/.config/herdr-app/mods/`)

All four are local-only. None calls `gh` or `fetch`, and none touches GitHub.

| Mod | What it shows for git | How (exec of `git`, on the focused terminal's machine) | Refresh |
|---|---|---|---|
| `changes` (`main.js`, 207 lines) | Uncommitted files of the focused pane's repo, each with its status (M/A/D/U) and `+/−`. Totals in the header. A virtual-scrolled diff of the selected file (first 1,000 files, 1,500 diff lines). A commit box (`git add -A` + `git commit -m`). | `rev-parse --show-toplevel`, `status --porcelain=v1 -z --untracked-files=all`, `rev-parse --verify HEAD`, `diff HEAD --numstat -z`, `diff HEAD -- <path>`. Rows group by machine (`hc machine ls --json`). | `status --porcelain=v2 --branch` (parses `# branch.head` and `# branch.ab`), `rev-parse --show-toplevel`, `rev-parse --path-format=absolute --git-common-dir` | Event-driven: a new space, a cd, the end of an agent's turn or a command, a machine coming back, `watchFolder` on the repo. **Gaps relative to the map (not covered by any shipped mod):**
- No commit history or graph.
- No PR, CI or check status.
- No PR or review-request list.
- No remote operations (fetch, pull, push).
- `spaces` shows ahead/behind versus **upstream**, not versus the default branch.

## 5. Takeaways for the spec

1. **Nothing covers all three features in one small mod without strings attached.** The fully featured ones fetch or build a sidecar binary: mrolafsson (Go, downloaded), munza `github-pr` (Go, built), reviewq (Rust), forge (Python + SQLite).
2. **The pattern that fits this machine is plain `exec("gh", …)` + `exec("git", …)` with `--json` output.** `gh` is installed and authed, and the mod needs no sidecar and calls `fetch` nowhere: ship-it, worktree-support, better-spaces, roundup, pr-review-assist and github-panel all do it this way. Every one of these still reaches the network through `gh`, and AGENTS.md wants that disclosed before adding.
3. **Git graph:** `rabeeh-ta/herdr-git-graph` is the clear base. It is pure `git`, has a detailed recipe and a tested lane layout. Two things to decide: (a) drop or keep its daily `fetch` to api.github.com for update checks, and (b) keep or drop its write menus (checkout, merge, rebase, reset, push and others). It is tested on 0.1.9 macOS only. `aBER0724/herdr-git-changes` reuses the same lanes and is tested on 0.1.11, which suggests the drawing code works on 0.1.11, but this is not verified here.
4. **PR + checks for the branch:** `ashrodan/ship-it`'s strip + `data.js` (`gh pr view` + `gh pr checks` + a GraphQL threads query) is the most complete reference. `obrunogonzaga`'s `ci.js` is the smallest. Showing it in the sidebar would mean cloning `spaces` (as better-spaces and worktree-support do). A separate mod would keep the shipped one.
5. **PR / review-request lists:** `NazzarenoGiannelli/herdr-roundup` has the best recipe for a cross-repo panel driven by `gh api graphql`. `mrolafsson/herdr-github` has the best UX to copy ("whose move it is" grouping) but can't be rebuilt from its recipe.
6. **Linux/WSL caveats:** several mods use macOS `open` (github-panel, worktree-actions, reviewq) and need `xdg-open` (or `wslview` on WSL). Most are tested only on macOS. Only aBER0724, dougcunha ci-dash and natelandau state 0.1.11. Both `miriarte33/herdr-pr-review-assist` and `sushmitsarmah/herdr-layouts` have no license.
7. Whichever base is picked, AGENTS.md says to build from the recipe when the files don't fit. `herdr-app check <mod>` is the acceptance gate.
